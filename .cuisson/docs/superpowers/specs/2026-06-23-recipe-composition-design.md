# Recipe Composition via `extends`

## Overview

Recipes can declare dependencies on other recipes using a new `extends` field in `recipe.json`. When a recipe is launched, its children are resolved and rendered automatically, with variables flowing from parent to child through an optional mapping layer.

## Data Model

### New `extends` Field in recipe.json

```json
{
  "name": "page",
  "variables": ["widgetName", "storeName"],
  "intent": ["create a page with component and store"],
  "extends": [
    {
      "recipe": "new-component",
      "variables": ["componentName"],
      "map": { "widgetName": "componentName" }
    },
    {
      "recipe": "new-store",
      "variables": ["storeName"]
    }
  ],
  "output": { ... }
}
```

Each `extends` entry:

| Field | Required | Description |
|-------|----------|-------------|
| `recipe` | Yes | Name of the child recipe to invoke (resolved from discovered recipes) |
| `variables` | Yes | Which variables this child needs, listed in resolution order. Defaults to the child's own `variables` if omitted |
| `map` | No | Maps parent variable names → child variable names. If a child variable name matches the parent's exactly, no mapping entry is needed |

### Go Struct Changes

In `cli/internal/discover/recipe.go`, add to the `Recipe` struct:

```go
type RecipeChild struct {
    Recipe     string            `json:"recipe"`
    Variables  []string          `json:"variables"`
    Map        map[string]string `json:"map,omitempty"`
}

type Recipe struct {
    Name      string          `json:"name"`
    Variables []string        `json:"variables"`
    Intent    []string        `json:"intent"`
    Output    Output          `json:"output"`
    Extends   []RecipeChild   `json:"extends,omitempty"`
}
```

## Launch Pipeline

### New Flow

```
cuisson launch <recipe> --var k=v
        │
        ▼
┌─────────────────────┐
│  Discover Recipes   │  Walk templates dir, find all recipe.json files
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│  Resolve Variables  │  Prompt for all of parent's variables
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│  Resolve Children   │  DFS: for each child, map parent vars → child vars
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│  Render Templates   │  For each node in tree (parent first, then children):
│                     │    read .tmpl → execute Go template → write output
└─────────────────────┘
```

### Composition Tree Walk (New Stage)

A new function `resolveChildren` in `cli/internal/render/recipe.go`:

1. Takes the parent's resolved variable map and a list of `RecipeChild` entries
2. For each child:
   - Resolves the child recipe by name from the discovered recipes map
   - Builds a child variable map: for each entry in `child.Variables`, look up the parent's resolved vars using `child.Map` (or direct name match if no mapping)
   - If the child itself has `extends`, recurse (pre-order DFS)
3. Returns a flat list of `(RecipeEntry, map[string]string)` pairs in pre-order traversal

### Pre-Order Traversal

Parent renders before children. This ensures configuration files generated by the parent are available when child templates execute.

### Error Handling

- If a child fails to render, the parent's files are already written (partial success is acceptable). Remaining siblings and their descendants are skipped.
- The error propagates up the call stack with context about which child in the tree failed.

## Validation Command

### New `validate` Subcommand

```bash
cuisson recipes validate [recipe-name]
```

- **No args** — validates all discovered recipes, reports every issue found
- **With recipe name** — validates that specific recipe and all its transitive children

### Checks Performed

| Check | Severity | Description |
|-------|----------|-------------|
| Circular dependencies | Error | DFS with visited tracking; reports the cycle path (e.g., `A → B → A`) |
| Missing child recipes | Error | `extends[].recipe` references a recipe not found in the discovered set |
| Missing variables | Error | A child needs a variable that no parent in the chain provides (via direct var or map) |
| Duplicate output paths | Warning | Two recipes in the same composition tree write to the same file |

### Output Format

```
$ cuisson recipes validate page
[✓] recipe "page" — no issues found

$ cuisson recipes validate new-component
[x] recipe "new-component": missing variable "componentName" — child needs it but no parent provides it
[!] recipe "new-component": duplicate output path "frontend/src/lib/components/MyButton/index.ts" — also written by parent
```

### Implementation Location

New file: `cli/cmd/recipes_validate.go` (Cobra command)
New package: `cli/internal/validation/` (validation logic)

## Edge Cases

| Case | Behavior |
|------|----------|
| Circular references (A → B → A) | Detected during DFS via visited set. Error: `"circular dependency detected: A → B → A"` |
| Missing child recipe | Error at launch time: `"unknown recipe 'foo' referenced by 'bar'"` |
| Missing variable in parent | Error: `"child 'new-component' requires variable 'componentName', not available in parent"` |
| Duplicate output paths | First write succeeds; subsequent writes skip with `[-] File already exists` (consistent with current behavior) |
| Unused parent variables | No warning. Extra vars in the resolved map are simply ignored by Go templates |

## Backwards Compatibility

Recipes without an `extends` field behave exactly as before. The `omitempty` tag on the Go struct ensures old recipe.json files remain valid JSON.
